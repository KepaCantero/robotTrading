# Claude Code Implementation Rules - AlgoTrading MVP

## 🎯 Requisitos OBLIGATORIOS para Cualquier Implementación

Antes de hacer **CUALQUIER commit**, la implementación DEBE pasar:

```bash
./scripts/check_all.sh
```

### ✅ Validaciones que se ejecutan:

#### 1. **FORMATEO Y ORDEN DE IMPORTS** (Auto-fix)
- [ ] **Black** - Formatea código Python (line-length=88)
- [ ] **Isort** - Ordena imports automáticamente
- [ ] **Autoflake** - Elimina imports y variables sin usar
- [ ] **Ruff** - Correcciones de estilo automáticas

#### 2. **LINTING Y REPORTES** (Deben estar limpios)
- [ ] **Flake8** - `flake8 app/ tests/ --max-line-length=100 --statistics`
  - Máximo tolerado: 5 errores E501 (lineas largas) por archivo
  - CERO errores E1, E2, E3, E4, E7, W1, W2, W3, W5
  - CERO errores F (undefined names, unused imports, etc.)
- [ ] **Pylint** - `pylint app/ tests/` (informativo, score > 8.0)

#### 3. **TYPE CHECKING**
- [ ] **Mypy** - `mypy app/ tests/` (sin errores críticos)
  - Allowed: warnings sobre typing incompleto en dependencias externas
  - CERO: Type mismatches en código propio

#### 4. **SECURITY CHECK**
- [ ] **Bandit** - `bandit -r app/ tests/ -ll` (sin HIGH severity issues)

#### 5. **TESTS**
- [ ] Si hay nuevas funciones: agregar unit tests
- [ ] Tests deben pasar: `pytest tests/ -v`
- [ ] Cobertura mínima: 80% para código nuevo

## 📋 CHECKLIST PRE-COMMIT

Antes de `git commit`, verifica:

```bash
# 1. Ejecutar chequeos y fixes automáticos
./scripts/check_all.sh

# 2. Revisar salida y corregir errores manuales si es necesario
# (Los auto-fixes no arreglan todo, algunos requieren cambios manuales)

# 3. Si hay errores de Flake8/Pylint pendientes, ejecutar:
cd scripts && python fix_linting_errors.py && cd ..

# 4. Revisar que no haya archivos temporales
git status

# 5. Hacer commit SOLO si:
# ✅ check_all.sh retorna código 0 (éxito)
# ✅ Flake8: máximo 5 errores E501 (líneas largas permitidas)
# ✅ Pylint: score > 8.0
# ✅ Mypy: sin errores críticos
# ✅ Bandit: sin HIGH severity issues
# ✅ Tests pasan (si aplica)
```

## 🚨 REGLAS ESTRICTAS

### ❌ PROHIBIDO hacer commit sin:
1. Ejecutar `./scripts/check_all.sh`
2. Que Black haya formateado el código
3. Que Isort haya ordenado imports
4. Flake8 clean (excepto máx 5 E501 por archivo)

### ⚠️ ADVERTENCIA: Tipos de errores a evitar
- **F821** (undefined name) - CERO tolerancia
- **F811** (redefinition) - CERO tolerancia
- **F601** (dict key repeated) - CERO tolerancia
- **E203** (whitespace) - CERO tolerancia
- **W291** (trailing whitespace) - CERO tolerancia

## 📊 MÉTRICAS DE ÉXITO

| Métrica | Umbral | Cómo verificar |
|---------|--------|----------------|
| Flake8 | ≤5 E501 por archivo | `flake8 app/ tests/ --max-line-length=100` |
| Pylint | >8.0 | `pylint app/ tests/` |
| Mypy | Sin errores críticos | `mypy app/ tests/` |
| Bandit | Sin HIGH severity | `bandit -r app/ tests/ -ll` |
| Coverage | >80% (código nuevo) | `pytest --cov` |
| Black | Format check | `black --check app/ tests/` |

## 🚀 FLUJO DE IMPLEMENTACIÓN COMPLETO

```
1. Escribir código
   ↓
2. Ejecutar: ./scripts/check_all.sh
   ↓
3. Si hay errores: corregir manualmente
   ↓
4. Verificar checks pasados (ver checklist arriba)
   ↓
5. git add -A
   ↓
6. git commit (con formato especificado)
   ↓
7. git push (si es necesario)
```

## ⚡ ATAJOS ÚTILES

```bash
# Ejecutar todos los checks en una línea
./scripts/check_all.sh && echo "✅ LISTO PARA COMMIT"

# Chequear solo Flake8 (rápido)
flake8 app/ tests/ --max-line-length=100

# Formatear SOLO archivos modificados (Git)
black $(git diff --name-only)
isort $(git diff --name-only)

# Ver qué cambiaría Black sin aplicar
black --check --diff app/
```
